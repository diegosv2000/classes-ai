01Hardware

La CPU y sus núcleos

La CPU ejecuta instrucciones. Un núcleo (core) es una unidad de procesamiento independiente dentro de la CPU: ocho núcleos significan, en potencia, ocho cosas haciendo progreso real al mismo tiempo. Compara tú mismo con un solo núcleo y con cuatro:

tick 0  ·  tareas terminadas 0

Cola de tareas

Terminadas

Núcleos

Con 1 núcleo el sistema operativo alterna tareas tan rápido que parece simultáneo; con más núcleos varias tareas corren realmente a la vez. Esa distinción es la raíz de "concurrencia vs paralelismo", dos secciones más adelante.

02Unidades de ejecución

Proceso vs Hilo

Son las dos unidades básicas de ejecución. Un proceso es un programa en ejecución con un entorno autónomo: conjunto completo y privado de recursos, en particular su propio espacio de memoria. Un hilo es la unidad de procesamiento más pequeña que el SO puede planificar; vive dentro de un proceso y todo proceso tiene al menos uno: el main thread.

ProcesoHilo
CreaciónCostosa: el SO construye un espacio de memoria completoLigera: reutiliza los recursos del proceso
MemoriaIndependiente: cada proceso tiene su espacio privadoCompartida: los hilos comparten memoria y archivos abiertos del proceso
ComunicaciónCompleja: requiere IPC — pipes o sockets, incluso entre máquinas distintasSencilla: leen y escriben las mismas variables… con riesgo de condiciones de carrera
ComplejidadReducida: los procesos están aislados entre síAlta: deben sincronizarse — interferencia, deadlocks

La comunicación entre procesos se apoya en mecanismos IPC (Inter-Process Communication) que ofrece el SO: pipes y sockets. Los sockets permiten incluso comunicar procesos de máquinas distintas — la puerta de entrada a los sistemas distribuidos de la semana 2.

03Planificación

El scheduler y los estados de un hilo

El planificador (scheduler) del sistema operativo decide qué hilo obtiene la CPU y por cuánto tiempo. Durante su vida, un hilo transita por estos estados — observa el ciclo que la ilustración recorre automáticamente:

Runnablelisto para ejecutar
Runningusando la CPU
Blockedesperando un recurso
Suspendedcedió la CPU voluntariamente
Resumedready tras estar bloqueado
Terminatedterminó su ejecución
Ruta típica: Runnable → Running → (Blocked | Suspended) → Runnable → … → Terminated

Los hilos tienen prioridades: en Java, un entero del 1 al 10. A mayor valor, más oportunidad de ejecutarse primero; con la misma prioridad, decide el sistema operativo.

Estos estados provienen del modelo conceptual del material del curso. Java moderno distingue sus estados oficiales en Thread.State: NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING y TERMINATED. Las ideas de fondo — listo, en ejecución, esperando un recurso — son las mismas en ambos modelos.

04El concepto central

Concurrencia vs Paralelismo

No son lo mismo. Concurrencia: las tareas progresan de forma entrelazada, aunque sea sobre un solo núcleo. Paralelismo: las tareas se ejecutan realmente al mismo tiempo en núcleos distintos.

Las tres tareas avanzan en el mismo instante.

Programación concurrente es escribir software que coordina tareas que progresan juntas. El software concurrente puede hacer varias cosas "a la vez": un procesador de texto responde al teclado mientras guarda y actualiza la pantalla. Es exactamente lo que empezarás a construir en la semana 1.

05El peligro

Memoria compartida y condición de carrera

Los hilos de un proceso comparten memoria: comunicación eficiente, pero peligrosa. Un incremento como contador++ parece una sola operación, pero son 3 pasos — leer, incrementar, guardar. Si los hilos se entrelazan sobre la misma data, aparece la interferencia de hilos. Ejecuta el entrelazado paso a paso:

Hilo Acontador++
contador = 0
memoria compartida
Hilo Bcontador--
Pulsa "Ejecutar entrelazado" y observa el paso a paso.

Resultado correcto (A y B en secuencia): contador = 0. Resultado con entrelazado: contador = -1 — la escritura de B sobrescribe la de A y su resultado se pierde. La respuesta a este problema son las herramientas de sincronización de la semana 5: synchronized, mutex, monitores, semáforos.

06Herramienta del curso

Repaso mínimo de Java

El curso programa hilos en Java. Cada aplicación arranca con un hilo principal (main thread), capaz de crear hilos adicionales, cada uno asociado a una instancia de Thread. Hay dos formas de definir un hilo:

1 · Implementar Runnable

public class HelloRunnable implements Runnable { public void run() { System.out.println("Hello from a thread!"); } public static void main(String[] args) { (new Thread(new HelloRunnable())).start(); } }

Recomendada: separa la tarea del mecanismo de ejecución.

2 · Extender Thread

public class HelloThread extends Thread { public void run() { System.out.println("Hello from a thread!"); } public static void main(String[] args) { (new HelloThread()).start(); } }

Funciona, pero consume la única herencia disponible.

  • Se llama a start(), no a run() directo: start() crea el nuevo hilo; run() directo ejecutaría el método en el hilo actual.
  • El hilo main es el punto de partida; desde él se crean y lanzan los demás.
  • La programación multi-threaded es más compleja: acceso compartido de objetos y riesgo de condición de carrera — ya lo viste en la sección 05.
  • Los estados del hilo (sección 03) aplican a estos objetos Thread.

07Fundamento distribuido

Redes: IP, puertos y protocolos

En la mitad "distribuida" del curso, tus programas se comunicarán por red. Cuatro piezas de vocabulario bastan para empezar:

Dirección IP

Identifica una máquina en la red (192.168.1.10; IPv4 de 4 bytes, IPv6 de 16). Como la dirección de un edificio. En Java la representa la clase InetAddress, que encapsula también el nombre de dominio.

Puerto

Identifica la aplicación o servicio dentro de la máquina (0–65535): el número del apartamento. El servidor escucha en un puerto; el cliente también vincula un puerto local durante la conexión.

TCP · confiable

Canal punto a punto confiable: mientras la conexión se mantenga activa, no se descartan datos y llegan en el mismo orden en que se enviaron. Requiere establecer una conexión previa. Es la base de los sockets de la semana 3.

UDP · rápido, sin garantías

Envía datagramas sin conexión ni confirmación: más ligero, pero los paquetes pueden perderse o desordenarse. Útil cuando la velocidad importa más que la fiabilidad (streaming, juegos).

Los datos viajan divididos en paquetes: cada uno lleva cabecera + payload (+ cola). Añadir cabecera es la encapsulación; quitarla en el destino, la decapsulación. Los routers eligen el camino de cada paquete; un gateway además convierte protocolos.

08Conexión

Cliente-servidor: la conexión TCP

El servidor ofrece un servicio y escucha en un puerto. El cliente debe conocer el hostname del servidor y su puerto, y se identifica con un puerto local. La conexión se establece con el saludo de tres vías — obsérvalo:

CLIENTEpuerto local
SERVIDORescuchando :puerto
SYN

Un socket es el extremo local de la conexión: cada programa escribe y lee en su socket para comunicarse. Cuando el servidor acepta una conexión, crea un socket nuevo para atender al cliente mientras el socket original sigue escuchando nuevas solicitudes. Lo programarás con ServerSocket, Socket e InetAddress en la semana 3.

09Desempeño

Latencia y throughput

Dos métricas centrales del desempeño en sistemas concurrentes y distribuidos (semanas 2 y 3):

Latencia

El tiempo que tarda una solicitud en viajar al destino y regresar con la respuesta. Depende de la distancia física, la congestión de red, el hardware y las ineficiencias de software. Latencia baja = respuesta rápida.

Throughput

La cantidad de tareas completadas por unidad de tiempo (ops/s, transacciones/s). Un sistema puede procesar miles por segundo y aun así tener alta latencia individual: cada solicitud espera en cola.

Distancia de la solicitudLatencia ida y vuelta (RTT) aprox. · valores ilustrativos
Mismo datacenter0.5 ms
Lima → Miami45 ms
Lima → Madrid90 ms
Lima → Tokio200 ms

En el trading de alta velocidad —el ejemplo del curso— unos pocos milisegundos deciden quién gana la operación. Por eso se optimizan los cuellos de botella: retrasos de propagación, transmisión, procesamiento y colas de espera. El desempeño también abarca uso de recursos, confiabilidad y escalabilidad: conservar la efectividad cuando crecen usuarios y recursos.
