01Sockets I · el marco

Cliente-servidor con TCP

En aplicaciones cliente-servidor, el servidor proporciona algún servicio y el cliente hace uso de él. La comunicación debe ser confiable: no se puede descartar datos, y estos deben llegar al cliente en el mismo orden en que el servidor los envió.

El protocolo TCP proporciona ese canal de comunicación punto a punto confiable que usan las aplicaciones cliente-servidor en Internet. Para comunicarse por TCP, ambos programas establecen una conexión: cada uno vincula un socket a su extremo de la conexión, y escriben y leen en ese socket para comunicarse.

cliente

su socket

conexión TCP confiable y en orden

servidor

su socket

Ese contrato — fiable, en orden, punto a punto — es lo que hace que Java pueda abstraerte del detalle: escribes y lees del socket como si fuera un archivo.

02Sockets I · la cita

Establecer la conexión

El cliente debe conocer el hostname de la máquina del servidor y el puerto donde escucha. Para solicitar la conexión intenta encontrarse con esa máquina y puerto, y para identificarse vincula un puerto local propio. Mira el proceso completo:

CLIENTEpuerto local
SERVIDORescuchando :puerto
solicitud
Se repite automáticamente

Detalle clave del material: al aceptar la conexión, el servidor necesita un nuevo socket para seguir escuchando al socket original (nuevas solicitudes) mientras atiende al cliente conectado. Para ello vincula el nuevo socket al mismo puerto local, con su endpoint remoto establecido a la dirección y puerto del cliente. Cada conexión TCP queda identificada por sus dos endpoints.

03Java · direcciones IP

InetAddress

Representa una dirección IP (IPv4 o IPv6) y encapsula también el nombre de dominio de dicha dirección. No tiene constructores: se crean objetos con sus métodos de fábrica (estáticos que devuelven una instancia de la misma clase).

Métodos de fábrica (estáticos)

getLocalHost()dirección del host local
getLoopbackAddress()dirección de loopback
getByName(host)IP de un host dado su hostname (nombre de máquina o texto de la IP). Con null retorna la interfaz de loopback
getByAddress(addr)objeto desde una IP sin procesar, en orden de red (byte de mayor orden primero): 4 bytes IPv4, 16 bytes IPv6

Métodos de instancia

getAddress()la IP sin procesar (byte[])
getHostAddress()la IP en forma textual (String)
getHostName()el nombre de host de esta IP
hashCode()código hash de la dirección IP

Patrón de diseño a observar: cuando la construcción es compleja o quieres cachear resultados (como resolver un DNS), los métodos de fábrica estáticos son la solución de Java — aquí por diseño, porque la clase ni siquiera expone constructores.

04Java · definición

Socket y el paquete java.net

Un socket es un endpoint de un enlace de comunicación bidireccional entre dos programas que se ejecutan en la red. Un socket está vinculado a un número de puerto para que la capa TCP pueda identificar la aplicación a la que van destinados los datos.

Un endpoint es una combinación de una dirección IP y un número de puerto. Cada conexión TCP puede ser únicamente identificada por sus dos endpoints:

endpoint A

IP + puerto

endpoint B

IP + puerto

conexión TCP única

El paquete java.net incluye un par de clases para una conexión bidireccional entre un programa Java y otro en la red: ServerSocket y Socket. Adicionalmente, URL (y URLConnection, URLEncoder) se prefieren si lo que quieres es conectarte a la web.

05Java · lado servidor

ServerSocket

Implementa un socket de servidor: espera solicitudes que llegan por la red, realiza operaciones en base a ellas y posiblemente retorna un resultado. Para instanciarlo basta indicar el puerto a vincular — y sus excepciones cuentan la historia completa:

// Constructor ServerSocket(int port) // puede arrojar: // - IOException : error de I/O al crear el socket // - SecurityException : un SecurityManager lo prohíbe // - IllegalArgumentException : puerto fuera de 0-65535

Dos observaciones del material

  • Con puerto 0, se toma un número de puerto asignado automáticamente.
  • La cola de solicitudes de conexión entrante tiene una longitud máxima de 50: si llega una solicitud con la cola llena, la conexión será rechazada.

Los dos métodos esenciales

  • Socket accept(): entra en estado de escucha y acepta una conexión. Bloquea el hilo hasta realizarla. Retorna un Socket vinculado a la nueva conexión.
  • synchronized void close(): cierra el socket; cualquier hilo bloqueado en accept() arrojará SocketException y liberará el bloqueo.

06Java · lado cliente

Socket: el cliente y sus streams

La clase Socket implementa un socket de cliente para comunicación bidireccional entre dos máquinas. Para instanciarlo necesitas la dirección IP (o hostname) del servidor y su puerto:

// Dos constructores equivalentes Socket(InetAddress address, int port) // por objeto InetAddress Socket(String host, int port) // por hostname textual

Los medios de la comunicación

  • InputStream getInputStream(): para leer. Arroja IOException si hay error de I/O, el socket está cerrado, no conectado, o su entrada fue apagada con shutdownInput().
  • OutputStream getOutputStream(): para escribir. IOException ante error de I/O o socket no conectado.

Observación importante

Estos streams solo sirven para leer y escribir arrays de bytes. Para trabajar con otros tipos u objetos hay que instanciar otras clases sobre el stream obtenido — exactamente lo que haremos en las siguientes slides con Scanner, PrintWriter, BufferedReader y los streams de objetos.

08Streams sobre el socket · I

Scanner y PrintWriter

InputStream con Scanner

Scanner se instancia sobre cualquier InputStream — por ejemplo, el del socket — y da acceso a todos sus métodos conocidos:

ServerSocket s = new ServerSocket(8181); Socket cliente = s.accept(); InputStream streamIn = cliente.getInputStream(); Scanner in = new Scanner(streamIn); String msg = in.nextLine(); // espera una línea System.out.println(msg);

PrintWriter

Imprime representaciones formateadas de objetos en un stream de salida de texto, a partir del OutputStream del socket:

PrintWriter out = new PrintWriter( cliente.getOutputStream()); PrintWriter out2 = new PrintWriter( cliente.getOutputStream(), true); // autoflush out.println("mensaje"); // print / println / printf

La variante con true activa el flush automático del buffer tras cada println, printf o format — sin ella, el mensaje puede quedarse en el buffer y nunca salir.

09Streams sobre el socket · II

InputStreamReader y BufferedReader

InputStreamReader · el puente

Es un puente entre stream de bytes y stream de caracteres: lee bytes y los decodifica en caracteres con un charset especificado o el charset por defecto. Se construye tomando como base un InputStream ya existente:

InputStreamReader(InputStream in)

Para máxima eficiencia, el material recomienda envolverlo con un BufferedReader.

BufferedReader · lectura eficiente

Lee texto almacenando caracteres en un búfer (se instancia sobre un Reader; InputStreamReader es una subclase de Reader). Con tamaño opcional (IllegalArgumentException si sz ≤ 0):

ServerSocket s = new ServerSocket(8181); Socket client = s.accept(); BufferedReader in = new BufferedReader( new InputStreamReader( client.getInputStream())); String line = in.readLine(); in.close();
  • read(): el carácter como entero, o -1 al final del stream.
  • readLine(): la línea sin el salto de línea, o null al final.

El patrón "socket → InputStreamReader → BufferedReader" es el estándar para leer texto de un socket en Java: el primero traduce bytes a caracteres, el segundo los agrupa en líneas de forma eficiente.

10Streams sobre el socket · III

ObjectOutputStream y ObjectInputStream

Cuando lo que viaja no es texto sino objetos Java completos, se serializan:

Escribir (serializar)

// ObjectOutputStream escribe primitivos y // grafos de objetos en un OutputStream OutputStream outStream = client.getOutputStream(); ObjectOutputStream out = new ObjectOutputStream(outStream); out.writeInt(12345); out.writeObject("Today"); out.writeObject(new Date()); out.close();

Leer (deserializar)

// ObjectInputStream deserializa lo escrito InputStream inStream = client.getInputStream(); ObjectInputStream in = new ObjectInputStream(inStream); int i = in.readInt(); String today = (String) in.readObject(); Date date = (Date) in.readObject(); in.close();

Reglas del material: los objetos se leen con readObject() y hay que castearlos al tipo esperado; deben leerse con los mismos tipos y en el mismo orden en que fueron escritos. Los primitivos van con sus métodos apropiados (readInt, etc.).

Y la pieza que queda: FilterOutputStream es la superclase de todas las clases que filtran streams de salida — se apoyan en un stream ya existente (que usan como sumidero básico), posiblemente transformando los datos o añadiendo funcionalidad en el camino.

11Redes · vocabulario

Términos de comunicación de red

La comunicación es la transferencia e intercambio de información entre personas, entre personas y cosas, y entre cosas. La comunicación de red es la que ocurre entre dispositivos terminales a través de una red de computadoras. La transferencia virtual de información funciona como la transferencia de un objeto real. El vocabulario:

TérminoSignificado
Data payloadLa información que se transporta
PacketLa unidad de datos que se conmuta y transmite por la red
Header / TailSegmento de información añadido antes (cabecera) o después (cola) del payload
EncapsulationAñadir header y tail al payload para formar el nuevo paquete
DecapsulationQuitar header y tail del paquete para obtener el payload
GatewayDispositivo con conversión de protocolos, selección de rutas e intercambio de datos
RouterDispositivo que selecciona la ruta de reenvío de los paquetes
Terminal deviceDispositivo final del sistema de comunicación: emisor o receptor de datos

11aRedes · el hardware

Switch, router y firewall

Switch

El dispositivo más cercano a los usuarios, usado para acceder a la red y conmutar tramas de datos (data frames). Da acceso de red a los terminales — PCs y servidores. Trabaja en la capa 2.

Router

Dispositivo de capa de red que reenvía paquetes en Internet: según la dirección de destino de cada paquete, elige el camino hacia el siguiente router o el destino. Mantiene la tabla de ruteo, ejecuta protocolos de ruteo, aísla dominios de broadcast, da acceso WAN y hace NAT.

Firewall

Dispositivo de seguridad entre dos redes: monitoriza, restringe y modifica los flujos que lo atraviesan para blindar la información y el funcionamiento de la red interna. Control de acceso por políticas, autenticación, cifrado y VPN.

La jerarquía típica: el switch conecta tus terminales, el router decide hacia dónde viajan los paquetes entre redes, y el firewall vigila la frontera.

11bRedes · cobertura

LAN, MAN y WAN

Según la cobertura geográfica, las redes se clasifican en tres tamaños:

LAN · Local

Computadoras, servidores y dispositivos en un área geográfica reducida (generalmente unos miles de metros cuadrados). Ejemplos: la red de una oficina, un ciber, una casa.

MAN · Metropolitana

Red de comunicación establecida dentro de una ciudad. Ejemplos: MAN de banda ancha, redes educativas, enlaces privados municipales o provinciales.

WAN · Amplia

Cubre desde decenas hasta miles de kilómetros: conecta redes de múltiples ciudades o incluso países, con comunicación de larga distancia. Internet es una WAN típica.

El material usa la industria educativa como caso: campus con LAN por edificio, interconectados en una MAN universitaria, que a su vez se apoya en WAN para las sedes remotas.

11cRedes · disposición

Topologías de red

Una topología de red es la disposición estructurada con la que se interconectan los dispositivos (terminales, routers, switches) mediante medios de transmisión — pares trenzados, fibra óptica, etc. Se clasifican en:

Estrellatodos los nodos hacia un punto central
Busun medio común por el que circulan todos
Anillocada nodo conectado al siguiente, en círculo
Árboljerarquía de nodos, ramas que se subdividen
Malla totaltodos con todos: máxima redundancia
Malla parcialsolo algunos enlaces directos: compromiso costo-resiliencia

La topología define qué tan tolerante a fallos y qué tan costosa es la red — conecta directo con el desafío de tolerancia a fallos de la semana 2.

12Redes · el marco conceptual

El modelo de referencia OSI

Siete capas, cada una con una responsabilidad clara — de la aplicación del usuario hasta el cable:

7 · Aplicación — provee interfaces para las aplicaciones 6 · Presentación — traduce formatos de datos para que un sistema entienda al otro 5 · Sesión — establece, gestiona y termina sesiones entre aplicaciones 4 · Transporte — conexiones extremo a extremo (puerto a puerto) 3 · Red — transmite datos de un host a otro (direcciones IP) 2 · Enlace de datos — PDUs, Ethernet, direcciones MAC 1 · Física — convierte señales: ópticas, eléctricas u ondas electromagnéticas

El recorrido automático sigue el viaje de un paquete que baja por las capas en el emisor y sube en el receptor. El modelo OSI es conceptual — el que rige Internet real es el siguiente: TCP/IP.

12aRedes · el marco real

El modelo de referencia TCP/IP

La pila OSI es compleja; los protocolos TCP e IP están ampliamente usados en la industria, por lo que el modelo de referencia TCP/IP se convirtió en el marco dominante para describir la comunicación de red.

El stack TCP/IP

Aplicación — HTTP, FTP, Telnet, DNS… Transporte — TCP, UDP Internet (red) — IP, IPv6, ICMP… Acceso a red — Ethernet, WiFi, medios

¿Quién estandariza?

La pila define una serie de protocolos estándar. Los estandariza principalmente el IETF (Internet Engineering Task Force): una organización voluntaria responsable de desarrollar y mantener los protocolos y estándares de Internet.

A diferencia de OSI (teórico, 7 capas), TCP/IP es el modelo práctico: lo implementan todos los sistemas reales.

12bTCP/IP · capa por capa

Capa de aplicación

Provee interfaces para el software de aplicación para que las aplicaciones usen los servicios de red. Sus protocolos designan qué protocolo de transporte usarán (normalmente TCP o UDP). Los tres protocolos clásicos del material:

FTP

File Transfer Protocol: transfiere archivos de un host a otro para descargarlos o subirlos. Uno de los protocolos de aplicación más antiguos y simples.

Telnet

Protocolo estándar de inicio de sesión remoto: da a los usuarios la capacidad de operar un equipo a distancia como si estuvieran frente a él.

HTTP

Hypertext Transfer Protocol: uno de los protocolos más usados de Internet. Fue diseñado originalmente para publicar y recuperar páginas HTML — la base de la web.

Cuando en la semana pasada vimos URL/URLConnection en java.net, era precisamente para hablar HTTP sin gestionar el socket a mano.

12cTCP/IP · capa por capa

Capa de transporte: TCP y UDP

Un protocolo de transporte recibe datos del protocolo de aplicación, los encapsula con su cabecera propia, y ayuda a establecer una conexión extremo a extremo — puerto a puerto. La capa se divide en dos protocolos estrella:

TCP

Confiable y orientado a conexión: retransmite lo perdido y entrega en orden. Su cabecera es más grande (más control: números de secuencia, acks, ventana). Es lo que usan los sockets de la primera mitad de esta semana.

UDP

Ligero y sin conexión: cabecera mínima, sin garantías de entrega ni orden. La contrapartida: menor latencia y sobrecarga. Ideal para audio, video y juegos donde llegar "tarde" es lo mismo que nunca.

Los números de puerto: como la capa de transporte conecta proceso con proceso (puerto a puerto), el puerto identifica qué aplicación dentro del host recibe los datos — es la razón de ser del parámetro port de ServerSocket y Socket.

12dTCP/IP · capa por capa

Red, enlace de datos y física

Capa de red

Mientras el transporte conecta procesos en los hosts, la capa de red es responsable de transmitir los datos de un host a otro. Su protocolo de trabajo: cada router recibe el paquete, mira la dirección de destino y lo reenvía al siguiente salto hasta el host final.

Capa de enlace de datos

Entre la capa de red y la física: provee servicios a IP/IPv6. Sus PDUs viajan por la red local: Ethernet y las direcciones MAC (fuente y destino) identifican los dispositivos dentro del mismo segmento.

Capa física

Convierte los bits en señales físicas: ópticas, eléctricas u ondas electromagnéticas, según el medio de transmisión — par trenzado, fibra óptica, aire (WiFi). Aquí viajan los datos de verdad.

Recuerda la analogía de la introducción: tu Socket en Java vive en la capa de aplicación/transporte, pero cada mensaje baja — encapsulado — hasta convertirse en bits sobre un medio físico, y en el receptor sube de vuelta.

12eTCP/IP · el viaje completo

Encapsulación de extremo a extremo

En el emisor, los datos bajan por las capas y cada una añade su cabecera (encapsulación). El paquete ya encapsulado viaja por la red intermedia (routers que solo leen las capas bajas). En el receptor, sube y cada capa quita su cabecera (decapsulación). Observa:

datos · payload de la aplicación + cabecera TCP · transporte + cabecera IP · red (host a host) + cabecera Ethernet · enlace (salto a salto) bits · sobre el medio físico

Y la definición final que ata todo: un protocolo es un conjunto de reglas que rigen el intercambio de mensajes entre dos entidades que se comunican para lograr un fin — por ejemplo, pedir la hora. TCP es un protocolo; HTTP es un protocolo; el formato de tu mensaje en el socket es tu propio mini-protocolo.

13w3_1.pdf · refuerzo

Desempeño y latencia (refuerzo)

El tercer material de la semana repite el deck de desempeño y optimización para la latencia de la semana 2, con un añadido de enfoque: las estrategias y técnicas para mejorar la eficiencia y reducir los retrasos en la transmisión de datos y el procesamiento dentro de estos sistemas.

Lo que ya dominas

  • Latencia: tiempo de ida y vuelta de una solicitud.
  • Throughput: tareas completadas por período (ops/s, TPS, req/s…).
  • Cuellos de botella: propagación, transmisión, procesamiento, colas.

Por qué reaparece aquí

Ahora sabes qué viaja por la red: paquetes con cabeceras, por routers, sobre medios físicos. Cada capa y cada salto añade su retraso — el modelo de capas de esta semana es el mapa donde viven esos cuellos de botella.

Si el test te pregunta por latencia o throughput aquí, es el mismo contenido de la semana 2: "transmisión de datos" y "procesamiento" son los dos retrasos que este deck subraya.
